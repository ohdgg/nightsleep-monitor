## 1. Назначение и цели

### 1.1. Назначение

NightSleep — крошечная утилита трея для глубокого затемнения экрана. Она позволяет сделать экран темнее, чем позволяет аппаратный минимум подсветки и стандартный ползунок яркости Windows.

### 1.2. Принцип работы

Затемнение выполняется системным API Magnification: функция `MagSetFullscreenColorEffect` применяет к изображению всего рабочего стола цветовую матрицу 5×5, которая умножает яркость каналов R, G и B на коэффициент `1 − уровень/100`. Эффект применяется при сборке кадра, поэтому затемняются меню «Пуск», панель задач, миниатюры, подсказки и Aero Peek. Окон поверх экрана программа не создаёт. Яркость подсветки и гамма видеокарты не изменяются, поэтому метод не зависит от драйвера и монитора.

| Способ | Особенности |
|---|---|
| Ползунок яркости Windows | Упирается в аппаратный минимум подсветки, не работает на многих внешних мониторах |
| Гамма-рампа (`SetDeviceGammaRamp`) | Диапазон ограничен драйвером, часто сбрасывается играми и другими программами |
| **NightSleep (Magnification API)** | Затемнение до 90% (до 100% — по настройке), не зависит от драйвера и монитора, действует на весь рабочий стол, включая оболочку |

### 1.3. Цели (измеримые)

| № | Цель | Целевое значение |
|---|---|---|
| 1 | Размер единственного exe-файла | < 500 КБ |
| 2 | Память в простое (private working set, затемнение 0%) | < 5 МБ |
| 3 | Память при активном затемнении | < 6 МБ |
| 4 | Память при открытом окне настроек | < 10 МБ |
| 5 | Нагрузка на CPU в простое | 0% (только событийная модель, без опроса) |
| 6 | Холодный старт до появления иконки в трее | < 50 мс |
| 7 | Задержка от нажатия хоткея до смены яркости | < 30 мс |
| 8 | Зависимости времени выполнения | Только системные DLL Windows (без VC++ Redistributable, без WebView2, без .NET) |
| 9 | Права | Обычный пользователь, UAC не требуется |

### 1.4. Не-цели

- Linux/macOS (отдельные проекты).
- Управление реальной подсветкой через DDC/CI.
- Регулировка яркости отдельных окон и приложений.
- Расписания, профили, плавные анимации (см. раздел 12).
- Windows 8.1 и старше, Windows 10 ниже 1809.
- Тёмная тема и стилизация окна настроек под Fluent/Mica: окно использует стандартные системные контролы.
- Установщик в версии 1.0 (поставка в виде portable exe, см. раздел 10).

## 2. Принятые архитектурные решения

| № | Решение | Обоснование |
|---|---|---|
| D1 | Нативный Win32 без GUI-фреймворков и без WebView | Главный приоритет — малый размер и ОЗУ |
| D2 | Крейт `windows-sys` (сырые биндинги) вместо `windows` | Меньше кода и времени компиляции, `unsafe` изолируется в тонком слое `win.rs` |
| D3 | Горячие клавиши только через `RegisterHotKey`; low-level hook (`WH_KEYBOARD_LL`) не используется | Не нагружает систему на каждое нажатие клавиши в системе, реже вызывает антивирусы, не требует отдельного потока |
| D4 | Один поток, цикл `GetMessageW`, без `tokio` и без фоновых потоков | 0% CPU в простое, отсутствие гонок |
| D5 | Затемнение — цветовая матрица Magnification API на весь рабочий стол; один уровень для всех мониторов | Закрывает всю оболочку Windows 11 (меню «Пуск», панель задач, миниатюры), не требует окон; раздельные уровни по мониторам API не поддерживает (см. раздел 12) |
| D6 | Скрытое top-level окно-приёмник сообщений (не message-only) | Message-only окна не получают широковещательные сообщения (`WM_DISPLAYCHANGE`, `TaskbarCreated`, `WM_SETTINGCHANGE`) |
| D7 | Конфиг в простом текстовом формате `key=value` с ручным парсером, без `serde` | Экономия размера, формат тривиален |
| D8 | Окно настроек — нативный диалог из ресурса `.rc`, создаётся по запросу и уничтожается при закрытии | Ноль памяти и ресурсов, пока окно не нужно |
| D9 | Автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; состояние автозапуска хранится только в реестре, не в конфиге | Единый источник истины, права администратора не нужны |
| D10 | Single-instance через именованный mutex `Local\NightSleep_SingleInstance` | Достаточно для пользовательской сессии, префикс `Global\` не нужен |
| D11 | `panic = "abort"`, обработчик паники пишет в лог и завершает процесс | Хук паники возвращает единичную матрицу (`emergency_reset`); остальные случаи — п. 3.13 |
| D12 | Максимум затемнения по умолчанию 90%, значение 100% доступно только через `max_level` в конфиге | Защита от «чёрного экрана» из-за случайного нажатия хоткея |
| D13 | Язык интерфейса: русский и английский, таблицы строк в коде | Без внешних файлов локализации |
| D14 | Оверлей-окна (метод первых версий) удалены; Magnification API — единственный метод; запасного метода нет | Решение заказчика после теста 3 (раздел 14). Оверлей не мог перекрыть слои оболочки Windows 11, требовал обходов (Peek, подъём по событиям) и тратил видеопамять DWM |
| D15 | Сбой Magnification API не приводит к запасному методу: уровень сбрасывается до 0%, пишется лог, показывается уведомление | Простота и предсказуемость; экран не должен остаться в неопределённом состоянии |
| D16 | Эффект применяется только при уровне > 0: `MagInitialize` при включении, единичная матрица и `MagUninitialize` при 0% | Встроенная «Экранная лупа» Windows остаётся доступной, когда затемнение выключено; в простое нет ни ресурсов, ни событий |

## 3. Функциональные требования

### 3.1. Уровни затемнения

| Параметр | Значение |
|---|---|
| Диапазон | 0 … `max_level` (%), по умолчанию `max_level = 90`, допустимо 50…100 |
| Пресеты в меню трея | 0%, 10%, …, `max_level` с шагом 10 |
| Шаг по горячим клавишам | 5 / 10 / 15 / 20 %, по умолчанию 10 |
| Начальный уровень при первом запуске | 0% |
| Восстановление при запуске | По настройке `restore_on_startup` (по умолчанию включено) |

**Правила:**

- Хоткей «темнее»: `level = min(level + step, max_level)`. Хоткей «светлее»: `level = max(level - step, 0)`. Округление к сетке пресетов не выполняется.
- Если после хоткея уровень не равен ни одному пресету, в меню трея ни один пункт не отмечается.
- 0% означает «выключено»: применяется единичная матрица и вызывается `MagUninitialize`, эффект полностью снят.
- Любое ненулевое значение запоминается как `last_nonzero_level`.
- Коэффициент яркости: `alpha = (level * 255 + 50) / 100` (целочисленно, 90% → 230), `factor = 1 − alpha/255`; на диагональ матрицы для R, G, B ставится `factor` (функция `level::color_matrix`, юнит-тесты).
- При уменьшении `max_level` текущий уровень обрезается до нового максимума.

### 3.2. Затемнение (Magnification API)

**Механизм.** `MagInitialize` при первом ненулевом уровне, затем `MagSetFullscreenColorEffect` с матрицей 5×5 (R, G, B умножаются на `factor`; альфа, смещения и четвёртая строка единичные). Эффект применяется при композиции кадра ко всему рабочему столу, поэтому не зависит от слоёв окон. Из документации Microsoft: функция доступна с Windows 8 (`Magnification.dll`), единичная матрица возвращает исходные цвета.

**Правила:**

- Окон, хуков `SetWinEventHook` и таймеров опроса нет. В простое программа не получает системных событий.
- При уровне 0% вызывается `MagUninitialize`, библиотека не удерживается.
- Матрица применяется повторно при возврате из сна (`PBT_APMRESUMEAUTOMATIC`), разблокировке (`WTS_SESSION_UNLOCK`), `WM_SETTINGCHANGE` и смене конфигурации мониторов (`WM_DISPLAYCHANGE`, дебаунс 300 мс, таймер `TIMER_REFRESH`).
- Ошибка `MagInitialize` или `MagSetFullscreenColorEffect`: уровень сбрасывается до 0%, причина пишется в лог, пользователю показывается уведомление (D15).
- Права `uiAccess` и подпись не требуются (подтверждено тестом 3).

**Известные особенности и ограничения** (часть не проверялась, см. раздел 15):

- Один уровень на все мониторы.
- Встроенная «Экранная лупа» (`Win` + `+`) и системные цветовые фильтры используют тот же механизм и могут конфликтовать с затемнением.
- Эксклюзивный полноэкранный режим игр, защищённый рабочий стол (UAC), HDR, защищённое видео и попадание затемнения на скриншоты не проверялись.
- Остаётся ли эффект после принудительного завершения процесса, не проверялось: на этот случай есть `--reset-screen` (п. 3.13).

### 3.3. Глобальные горячие клавиши

| Действие | По умолчанию | Настраивается |
|---|---|---|
| Темнее | `Ctrl+Alt+PageDown` | Да |
| Светлее | `Ctrl+Alt+PageUp` | Да |
| Вкл/выкл (0% ↔ последний ненулевой) | `Ctrl+Alt+End` | Да |
| Аварийный сброс до 0% | `Ctrl+Alt+Shift+End` | **Нет** (фиксированный) |

Значения по умолчанию выбраны так, чтобы не конфликтовать с масштабом `Ctrl++`/`Ctrl+-` в браузерах и редакторах.

**Требования:**

- Регистрация через `RegisterHotKey` на окно-приёмник, идентификаторы 1…4.
- Для «темнее» и «светлее» флаг `MOD_NOREPEAT` не ставится (удержание клавиши меняет уровень непрерывно). Для «вкл/выкл» и аварийного сброса `MOD_NOREPEAT` ставится.
- Хоткей обязан содержать хотя бы один модификатор из `Ctrl` / `Alt`, при этом комбинации «только Shift» и «Shift+клавиша без Ctrl/Alt» запрещены. Клавиша `Win` в v1.0 не поддерживается.
- Три настраиваемых хоткея должны быть различны между собой и не совпадать с аварийным.
- Если регистрация не удалась (комбинация занята другим приложением), событие записывается в лог, а пользователь видит уведомление из трея (`NIF_INFO`) с названием действия. Остальные хоткеи продолжают работать.
- Работа в окнах, запущенных от администратора: `RegisterHotKey` обычно срабатывает и при фокусе в таких окнах. Поведение проверяется на этапе 4 и документируется в README по фактическому результату.

### 3.4. Иконка и меню в трее

**Иконка:** `Shell_NotifyIconW` с `NOTIFYICON_VERSION_4`, идентификация по `uID` (без GUID, чтобы перемещение exe не ломало иконку). Две иконки: обычная (уровень 0%) и затемнённая (уровень > 0). Загрузка через `LoadIconMetric(LIM_SMALL)` для корректного размера при любом DPI. Подсказка: `NightSleep — 30%`.

**Левый клик:** переключение 0% ↔ `last_nonzero_level`. Если `last_nonzero_level` отсутствует — 30%.

**Правый клик — контекстное меню** (`TrackPopupMenu`, с обязательным `SetForegroundWindow` до и `PostMessage(WM_NULL)` после):

```
NightSleep                    (заголовок, неактивный)
─────────────────────
● 0%  (выкл)
○ 10%
○ 20%
…
○ 90%
─────────────────────
Настройки…
Автозапуск                    ✓
─────────────────────
О программе
Выход
```

- Список уровней строится динамически по `max_level`; отмечается пункт, равный текущему уровню (`MFT_RADIOCHECK`).
- Пункт «Автозапуск» читает и переключает состояние в реестре и синхронизирован с одноимённым чекбоксом в настройках.
- Двойной клик по иконке открывает «Настройки».

**Перезапуск `explorer.exe`:** по сообщению `TaskbarCreated` (регистрируется через `RegisterWindowMessageW`) иконка добавляется заново.

**Первый запуск** (конфиг отсутствует): всплывающее уведомление с подсказкой, какими клавишами управлять затемнением.

### 3.5. Окно настроек

Модальный диалог, создаваемый по запросу (`DialogBoxParamW`) из ресурса `.rc`, на стандартных контролах. Закрытие окна полностью освобождает его ресурсы. Размеры заданы в диалоговых единицах (DLU), поэтому окно корректно масштабируется при Per-Monitor DPI v2.

**Группа «Горячие клавиши»:**

- Три поля на базе стандартного контрола `msctls_hotkey32` (захват комбинации выполняет сам контрол): «Темнее», «Светлее», «Вкл/выкл».
- Правила контрола (`HKM_SETRULES`) запрещают комбинации без Ctrl/Alt; запасная комбинация при нарушении — `Ctrl+Alt`.
- Рядом — неактивная строка с текстом аварийного хоткея.
- Валидация при нажатии «ОК»: уникальность комбинаций и успешная регистрация. Если новая регистрация не удалась, откатываются старые хоткеи, пользователь видит сообщение с причиной, а диалог остаётся открытым.

**Группа «Поведение»:**

- Выпадающий список «Шаг изменения»: 5 / 10 / 15 / 20 %.
- Чекбокс «Восстанавливать уровень при запуске».
- Чекбокс «Запускать вместе с Windows».
- Выпадающий список «Язык»: Авто / Русский / English (смена применяется после закрытия диалога без перезапуска).

**Кнопки:** «ОК», «Отмена». Параметры применяются и сохраняются только по «ОК».

**«О программе»:** отдельный диалог с названием, версией (`CARGO_PKG_VERSION`), краткой строкой назначения, названием лицензии и адресом репозитория (`CARGO_PKG_REPOSITORY`).

### 3.6. Конфигурация

**Файл:** `%APPDATA%\NightSleep\config.ini` (путь берётся из переменной окружения `APPDATA`, каталог создаётся при необходимости).

**Формат:** строки `key=value`, комментарии с `;` в начале строки, кодировка UTF-8 без BOM.

```ini
; NightSleep configuration
version=1
level=30
last_nonzero_level=30
step=10
max_level=90
restore_on_startup=1
language=auto
hotkey_dim_more=Ctrl+Alt+PageDown
hotkey_dim_less=Ctrl+Alt+PageUp
hotkey_toggle=Ctrl+Alt+End
```

**Требования:**

- Парсер ручной, без внешних крейтов. Неизвестные ключи (в том числе устаревший `method=` из версий с оверлеем) игнорируются и при сохранении не переносятся. Некорректное значение отдельного поля заменяется значением по умолчанию, остальные поля применяются.
- Если файл нельзя прочитать как текст, он переименовывается в `config.ini.bak` и создаётся новый с настройками по умолчанию.
- Запись атомарная: запись во временный файл `config.ini.tmp`, затем `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`.
- Запись выполняется с задержкой 1 с после последнего изменения (таймер), а также принудительно при выходе и завершении сеанса. Это исключает запись на диск при каждом нажатии удерживаемого хоткея.
- Поле `version` обязательно; при версии выше известной файл читается «как получится» и не перезаписывается чужим форматом до явного изменения настроек пользователем.
- Формат записи хоткея: модификаторы `Ctrl`, `Alt`, `Shift` через `+`, затем имя клавиши (`A`–`Z`, `0`–`9`, `F1`–`F24`, `Up`, `Down`, `Left`, `Right`, `Home`, `End`, `PageUp`, `PageDown`, `Insert`, `Delete`, `Minus`, `Plus`, `Comma`, `Period`, `Num0`–`Num9`). Клавиши вне таблицы записываются как `0xNN` (шестнадцатеричный VK-код).

### 3.7. Автозапуск

- Значение `NightSleep` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, содержимое: `"<полный путь к exe>" --autostart`.
- Путь определяется через `std::env::current_exe()`.
- Если автозапуск включён, а записанный путь не совпадает с текущим (exe перенесён), запись обновляется при запуске.
- Состояние автозапуска читается из реестра, дублирования в `config.ini` нет.

### 3.8. Параметры командной строки

| Параметр | Действие |
|---|---|
| `--autostart` | Запуск из автозапуска (без побочных эффектов, служит маркером в логе) |
| `--reset` | Сбросить сохранённый уровень на 0% и запустить как обычно |
| `--reset-screen` | Автономное восстановление: применить единичную цветовую матрицу Magnification и завершить процесс (если затемнение осталось после сбоя) |
| `--cleanup` | Снять цветовой эффект Magnification, удалить запись автозапуска и каталог `%APPDATA%\NightSleep`, затем завершить процесс (для ручного удаления без следов) |

### 3.9. Жизненный цикл

**Запуск:**

1. Создать mutex `Local\NightSleep_SingleInstance`. Если он уже существует: найти скрытое окно по имени класса `NightSleepMsgWnd`, отправить `PostMessageW(WM_APP_SHOW_SETTINGS)` и завершиться.
2. Разобрать параметры командной строки.
3. Загрузить конфиг.
4. Создать окно-приёмник, зарегистрировать `TaskbarCreated`, `WTSRegisterSessionNotification`.
5. Зарегистрировать хоткеи.
6. Создать иконку в трее.
7. Применить сохранённый уровень (если `restore_on_startup = 1`); при уровне 0% — `force_reset` на случай эффекта, оставшегося от прерванного запуска.
8. Войти в цикл сообщений.

**Завершение** (меню «Выход», `WM_ENDSESSION`, `WM_QUERYENDSESSION`):

1. Немедленно записать конфиг с текущим уровнем (**без** предварительного сброса в 0%, иначе при следующем запуске восстановится 0).
2. Удалить иконку (`NIM_DELETE`), разрегистрировать хоткеи и уведомления сессии.
3. Вернуть единичную матрицу и вызвать `MagUninitialize`; уничтожить окно-приёмник.

### 3.10. Граничные случаи

| Случай | Поведение |
|---|---|
| Изменение конфигурации мониторов | Эффект применяется повторно после дебаунса 300 мс, уровень сохраняется |
| Блокировка экрана (`Win+L`) | Экран блокировки — другой рабочий стол; после разблокировки эффект применяется повторно |
| Сон / гибернация | Эффект применяется повторно по событию возобновления |
| UAC-запрос (secure desktop) | Влияние не проверялось (ограничение Windows) |
| Эксклюзивный полноэкранный режим игры (DirectX/Vulkan) | Не проверялось; документируется в README |
| Перезапуск `explorer.exe` | Иконка создаётся заново по `TaskbarCreated` |
| Аварийное завершение процесса (panic) | Хук паники пишет в лог и возвращает единичную матрицу |
| Принудительное завершение (Диспетчер задач) | Остаётся ли эффект, не проверялось; восстановление — `--reset-screen` или повторный запуск программы с уровнем 0% |
| Ошибка Magnification API | Уровень 0%, лог, уведомление (D15) |
| Занятая комбинация хоткея | См. п. 3.3 |
| Скриншоты | Попадание затемнения на снимки не проверялось. Документируется |
| Повреждённый конфиг | См. п. 3.6 |
| Aero Peek, миниатюры, подсказки, меню «Пуск», панель задач | Затемняются системой при сборке кадра (подтверждено тестом 3) |
| `Win+D`, `Win+M` | Затемнение не зависит от окон, проблема снята (не проверялось отдельно) |
| «Экранная лупа» Windows, цветовые фильтры | Возможен конфликт; не проверялось |

### 3.11. Локализация

- Языки: русский, английский.
- Строки хранятся в `i18n.rs` в виде статических таблиц (`enum Str` → `&'static str` на каждый язык). Внешних файлов локализации нет.
- Язык «Авто» определяется по `GetUserDefaultUILanguage()` (русский основной язык → `ru`, иначе → `en`); пользователь может зафиксировать язык в настройках.
- Диалоги используют единый шаблон в `.rc`, текст элементов проставляется в `WM_INITDIALOG` через `SetDlgItemTextW`.

### 3.12. Логирование

- Файл `%APPDATA%\NightSleep\log.txt`, формат строки: `ГГГГ-ММ-ДД ЧЧ:ММ:СС [уровень] сообщение` (время UTC от `GetSystemTimeAsFileTime` или `SystemTime`).
- Логируются только предупреждения и ошибки (неудача регистрации хоткея, ошибки создания окон, панику) плюс события запуска и завершения.
- Файл открывается на время записи и закрывается сразу (постоянного дескриптора нет).
- Ротация: при превышении 256 КБ `log.txt` переименовывается в `log.old.txt` (старый `log.old.txt` перезаписывается).
- Ошибки логирования никогда не прерывают работу приложения.

### 3.13. Откат и защита от «залипшего» затемнения

Запасного метода затемнения нет (D14), поэтому возврат экрана к нормальному состоянию защищён несколькими независимыми уровнями:

1. Аварийный хоткей `Ctrl+Alt+Shift+End` — 0% (единичная матрица); комбинация фиксирована и не может быть назначена другому действию.
2. Меню трея и хоткеи: уровень 0% полностью снимает эффект (`MagUninitialize`).
3. Выход, завершение сеанса (`WM_ENDSESSION`) и паника (`emergency_reset` в хуке паники) восстанавливают единичную матрицу.
4. Ошибка Magnification API: уровень сбрасывается до 0%, запись в лог, уведомление (D15).
5. При запуске с уровнем 0% выполняется `force_reset` — на случай, если предыдущий запуск завершился сбоем с наложенным эффектом.
6. `--reset-screen` (и `--cleanup`) восстанавливают экран из отдельного процесса.
7. Возврат к прежнему методу (оверлею) возможен только через историю git (коммиты `7ce1335`, `55e5584`, ветка с экспериментом `feature/magnifier-method`).

**Правила кода:**

- `unsafe` допускается только в `win.rs`, `magnifier.rs`, `tray.rs`, `settings.rs`, `app.rs`, `autostart.rs` и снабжается комментарием `// SAFETY:`. Модули `level.rs`, `config.rs` (разбор), `hotkey.rs` (разбор), `i18n.rs` — без `unsafe`.

- Ресурсы Win32 (окна, хэндлы реестра, иконки, меню) оборачиваются в типы с `Drop`.
- Ошибки: единый тип `Error` с кодом и описанием, возвращаемый из `Result`. Панику заменяет лог и аварийное завершение (D11).

### 4.5. Потоковая модель и сообщения

- Один поток: все окна, хоткеи, трей и таймеры обслуживаются основным циклом.
- Собственные сообщения: `WM_APP+1` — события трея; `WM_APP+3` — показать настройки (от второго экземпляра).
- Таймеры: `TIMER_SAVE` (1 с, отложенное сохранение), `TIMER_REFRESH` (300 мс, дебаунс смены мониторов). Опрошающих таймеров нет.

Манифест встраивается в exe и содержит:

- `dpiAwareness = PerMonitorV2` (с запасным `dpiAware = true/pm`);
- зависимость от Common Controls 6.0 (`Microsoft.Windows.Common-Controls` версии 6.0.0.0), чтобы контролы выглядели современно;
- `supportedOS` Windows 10/11;
- `requestedExecutionLevel level="asInvoker"`.

### 4.8. Безопасность и устойчивость

- Права администратора не требуются и не запрашиваются.
- Приложение не использует сеть, не устанавливает системные хуки ввода, не внедряется в другие процессы.
- Единственные записи вне каталога `%APPDATA%\NightSleep`: значение автозапуска в `HKCU\...\Run`.
- Все ошибки Win32 при создании окон и регистрации хоткеев обрабатываются, приложение продолжает работу в деградировавшем режиме (например, без хоткеев) и пишет причину в лог.
- Аварийный хоткей (`Ctrl+Alt+Shift+End`) регистрируется всегда; если он не зарегистрирован, пользователь получает уведомление при запуске.

## 10. Лицензия и распространение

- **Лицензия:** `MIT OR Apache-2.0` (стандартная двойная лицензия экосистемы Rust; совместима с лицензиями `windows-sys` и `embed-resource`). Файлы `LICENSE-MIT` и `LICENSE-APACHE` лежат в корне репозитория, поле `license` указывается в `Cargo.toml`. Окончательное решение остаётся за владельцем проекта.
- **Форма поставки v1.0:** zip-архив с одним `nightsleep.exe`, `README.md` и текстами лицензий. Установка не требуется.
- **Удаление:** отключить «Запускать вместе с Windows» в настройках (или запустить `nightsleep.exe --cleanup`), затем удалить exe. Полное удаление следов: `--cleanup` удаляет запись автозапуска и каталог `%APPDATA%\NightSleep`.
- **Установщик** (Inno Setup/NSIS) и публикация в winget/Scoop — планы после 1.0.
- **Подпись кода:** желательна для снижения предупреждений SmartScreen, в v1.0 не обязательна.

## 14. Результаты тестирования на Windows 11

Тестировал заказчик на Windows 11 (по виду панели задач), запись экрана 1920×1080; число мониторов не уточнялось. Уровень затемнения около 50%. Видео разобраны покадрово; яркость кадров измерена программно (средняя яркость 0–255, значения для сравнения: фон без затемнения 12,4; с затемнением 5,9; панель задач 35 и 17 соответственно).

### 14.1. Тест 1 («ekran-1»), версия `7ce1335`

| Время | Событие | Результат |
|---|---|---|
| 0–3 с | Затемнение включено, курсор на панели задач | Затемнены и рабочий стол, и панель задач (оверлей над панелью задач работает) |
| 3,0–3,5 с | Наведение на кнопку приложения | Миниатюра **не затемнена** (яркость 186 против 20 вокруг) |
| 4,0–5,5 с | Курсор переходит на миниатюру (Aero Peek) | **Весь экран полностью светлый** (233 вместо 5,7), оверлей исчез на ~1,5 с |
| 5,5 с | Курсор уходит | Затемнение возвращается |
| 6,5–11,5 с | Панель трея и подсказка | Всплывающая панель затемнена; текст подсказки светлее фона |

Диагноз: (1) Peek скрывает все окна, кроме просматриваемого; (2) миниатюры и подсказки создаются позже оверлея и оказываются выше. Исправлялось в оверлее (коммит `55e5584`); после перехода на Magnification API неактуально.

### 14.2. Тест 2 («ekran-2»)

Видео записано после выхода коммита `55e5584`, но какой именно exe использовался (до или после исправлений Peek и миниатюр), не уточнялось. Исправления Peek и миниатюр в этом видео не проверялись.

| Время | Событие | Результат |
|---|---|---|
| 0–1,4 с | Затемнение выключено, клик по лампочке во всплывающей панели трея | Включается затемнение |
| 1,5–4,5 с | Затемнение включено | Всплывающая панель трея затемнена нормально |
| 5,0–7,5 с и 11,0–12,5 с | Открыто меню «Пуск» | Меню **полностью яркое**; **панель задач тоже яркая** (35 вместо 17), фон тёмный |
| 8,0–8,5 с | Меню закрыто | Панель задач остаётся яркой ещё около секунды |
| 16,5 с | Затемнение выключено лампочкой | Нормальная яркость |

Диагноз: меню «Пуск» (и панель задач на время его показа) находятся в более высоком слое окон, чем оверлей; порядок `TOPMOST` слои не пересекает. Не решается подъёмом оверлея; это стало главной причиной перехода на Magnification API.

### 14.3. Тест 3: Magnification API

Заказчик проверил экспериментальный метод на Windows 11 (PR #1, коммит `c16ab54`): **«Magnifier идеально работает!»** Меню «Пуск» и панель задач затемняются. Подробные сценарии (Peek, миниатюры, `Win+D`, сон, второй монитор, «Экранная лупа») по отдельности не фиксировались. Решение: Magnifier — единственный метод, оверлей удалён (D14).

### 14.4. Прочее

- Заказчик подтвердил, что в целом приложение работает.
- Тест `Win+M` / `Win+D` / «Показать рабочий стол» остался без результатов и после перехода на Magnification API неактуален.
- CI на Windows: сборка, `clippy`, тесты и проверка размера проходят.
